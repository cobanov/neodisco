# Minimal creation interface, 2026-09-07

The interface keeps a kiosk-oriented interaction: choose one of six preset frames,
write a prompt, create an image, and revisit it in the history strip. The centered
composer is retained. Desktop history runs vertically on the left, with a
persistent, read-only metadata panel on the far right. The visual language follows vggtq and vgpu-umaps: Foundry Gridnik, absolute black,
a monochrome gray ramp, square controls and restrained measurement lines. Primary
controls retain 44px touch targets. Color belongs to the generated images. Studio
WOFF2 files are provisioned separately into `neodisco/web/fonts/`; they are excluded
from the public repository.

Finished images fit the available canvas without cropping. The right panel contains the prompt, metadata, image/settings downloads and prompt
reuse. Reuse carries prompt weights and a supported frame; hidden historical model
settings and seed are not reapplied. The frame selector returns to composition: it removes the previous result from
the canvas and displays a correctly fitted empty frame with pixel dimensions.
The previous result remains in history and the current prompt is preserved.

Submission requires a nonempty prompt. Enter inserts a newline; Command/Control +
Enter submits. The client prevents duplicate submissions and history changes during
a run, shows queue/step/ETA feedback and actual preview frames, restores its unfinished
job after reload, and unlocks after a missing or failed job. Image loads use version
checks so a slower earlier selection cannot overwrite a newer one. Model defaults
remain 250 scheduled steps minus 10 skipped steps, with random seed.

## Validation

- Chrome/Playwright interaction checks against an isolated API fixture: preset payload,
  240 effective steps, Enter behavior, queue/running/completion, details with seed 0,
  prompt reuse, unfinished-job reload, and 404 recovery.
- No horizontal overflow at widths 320, 390, 768, 1440 and 1920; desktop and mobile
  screenshots inspected. Reduced motion disables decorative animation.
- Read-only live API verification with all 12 existing jobs, result PNG/JSON and a
  portrait image. No new GPU render was submitted for UI testing.
- No browser JavaScript errors in these checks. `node --check` and `git diff --check` pass.
- Local evidence: `benchmark-results/ui-studio-20260907/` (gitignored).

These checks exercise the client and existing API; they do not measure rendering
performance or constitute a full physical kiosk acceptance test.

## Frame selection and English-only follow-up

The RAS interface is English-only. The language selector, translations and locale
persistence have been removed; an old `localStorage.lang=tr` has no effect.
All six preset frames were checked after selecting history and after completion,
including mobile resizing, prompt/history preservation and return to an empty
pixel-labelled frame. Evidence: `benchmark-results/ui-frame-english-20260907/`.

## Efficient desktop layout follow-up

Vertical history returns to the left, with persistent metadata on the far right. The stage grows to
use the recovered height and aligns the image's bottom with the controls. Empty
status rows no longer reserve space. At1440×950, the same5:3 image measures
1020×612px rather than628×377px; the gap to aspect controls is8px rather than56px.
History scrolling is preserved when selecting images. Metadata reflects pending,
running and completed jobs, including seed0. Mobile keeps a horizontal history
strip and readable metadata below the main interaction instead of squeezing
sidebars beside the image. Evidence: `benchmark-results/ui-layout-20260907/`.

## Readability and spacing follow-up

The masthead uses one brand hierarchy and shares the workspace's outer margins.
A24px separation keeps both sidebars clear of its divider. At1440px the metadata

Below900px the layout stacks to preserve readable text and usable canvas width.

## Combinatorial examples, 2026-09-08

Example now assembles English prompts from six coherent worlds: orbital scenes,
alien landscapes, underwater worlds, dream architecture, nature and retrofuturistic
cities. Each world has four subjects, four settings, four details and five artists.
Two distinct artists are combined with one of eight palettes, five lighting choices
and three composition finishes. The original scene / artist / Artstation structure
is retained. A shuffled deck visits all 24 subjects before repeating and avoids a
subject repeat across deck boundaries. There is no extra control or generation call;
the button fills the editable prompt, updates draft metadata and keeps keyboard focus.

Checks: 240 assembled prompts cover each subject once per deck without adjacent
subject repeats; 24 browser clicks produce distinct prompts and preserve the frame,
metadata and focus without submitting a render. Mobile layout also checked.
Local evidence: `benchmark-results/prompt-builder-20260908/`.
