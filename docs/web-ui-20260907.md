# Minimal creation interface, 2026-09-07

The interface keeps a kiosk-oriented interaction: choose one of six preset frames,
write a prompt, create an image, and revisit it in the history strip. The centered
composer is retained; permanent technical sidebars are removed. Warm dark surfaces,
a restrained lilac accent, consistent typography and 44px primary touch targets
provide the visual hierarchy.

Finished images fit the available canvas without cropping. Download is next to the
image. A native modal contains the prompt, metadata, settings download and prompt
reuse. Reuse carries prompt weights and a supported frame; hidden historical model
settings and seed are not reapplied. The frame selector configures the next image
without changing the displayed image's aspect ratio.

Submission requires a nonempty prompt. Enter inserts a newline; Command/Control +
Enter submits. The client prevents duplicate submissions and history changes during
a run, shows queue/step/ETA feedback and actual preview frames, restores its unfinished
job after reload, and unlocks after a missing or failed job. Image loads use version
checks so a slower earlier selection cannot overwrite a newer one. Model defaults
remain 250 scheduled steps minus 10 skipped steps, with random seed.

## Validation

- Chrome/Playwright interaction checks against an isolated API fixture: preset payload,
  240 effective steps, Enter behavior, queue/running/completion, details with seed 0,
  prompt reuse, English/Turkish, dialog Escape, unfinished-job reload, and 404 recovery.
- No horizontal overflow at widths 320, 390, 768, 1440 and 1920; desktop and mobile
  screenshots inspected. Reduced motion disables decorative animation.
- Read-only live API verification with all 12 existing jobs, result PNG/JSON and a
  portrait image. No new GPU render was submitted for UI testing.
- No browser JavaScript errors in these checks. `node --check` and `git diff --check` pass.
- Local evidence: `benchmark-results/ui-studio-20260907/` (gitignored).

These checks exercise the client and existing API; they do not measure rendering
performance or constitute a full physical kiosk acceptance test.
